# CherryPicker MVP 요구사항

- 문서 상태: 최초 지원 카드와 승인취소 집계 정책 확정
- 최초 지원 카드: MG 더나은 체크카드
- 최소 지원 버전: iOS 27
- 기준일: 2026-08-11
- 기준 아키텍처: [`docs/ARCHITECTURE.md`](ARCHITECTURE.md)

## 1. MVP 목표

MG 더나은 체크카드의 승인 및 승인취소 문자를 iPhone 단축어로 받아 거래를 유실 없이 저장하고, 사용자가 거래별 실적 인정 여부와 혜택 수령 여부를 직접 기록한 뒤 현재 현황을 확인할 수 있게 한다.

MVP의 성공 여부는 카드 정책을 완전히 자동 판정하는지가 아니라 다음 세 가지로 판단한다.

1. 승인 및 취소 문자가 앱에 안정적으로 저장된다.
2. 사용자가 파싱 결과를 확인하고 잘못된 값을 수정할 수 있다.
3. 사용자가 확정한 판정을 바탕으로 실적과 혜택 현황을 볼 수 있다.

## 2. 확인된 입력 형식

### 2.1 체크승인

```text
[Web발신]
MG카드(4775)체크승인
{사용자명}
2,500원
08/03 18:00
씨유(CU)삼성백암점
통장잔액426,905원
```

```text
[Web발신]
MG카드(4775)체크승인
{사용자명}
7,700원
08/03 16:40
네이버페이
통장잔액425,605원
```

### 2.2 승인취소

```text
[Web발신]
[승인취소]
MG체크카드(4775).{사용자명}.
3,800원.
08/03.취소완료.
네이버페이
```

### 2.3 입력 형식에서 확인된 제약

- 승인과 취소의 줄 구성 및 구분 문자가 다르다.
- 문자는 카드 번호 전체가 아니라 끝 네 자리만 제공한다.
- 거래 일시에는 연도가 없다.
- 취소 문자에는 취소 완료 시각과 원승인 식별자가 없다.
- 취소 문자의 금액, 날짜, 가맹점만으로 원거래를 항상 정확히 찾을 수 없다.
- 승인 문자에 포함된 통장 잔액은 거래 관리의 핵심 정보가 아니다.

## 3. 사용자 흐름

```text
승인 또는 취소 문자 수신
  → 단축어 자동화가 문자 원문을 CherryPicker에 전달
  → 앱이 원문을 먼저 저장
  → 파서가 거래 후보 값을 추출
  → 사용자가 미확인 거래를 검토하고 판정
  → 카드 현황에 사용자가 확정한 결과를 반영
```

## 4. 기능 요구사항

### 4.1 카드 설정

- 사용자는 MG 더나은 체크카드를 등록할 수 있어야 한다.
- 최초 실행 시 `MG 더나은 체크카드`(카드사 `MG`, 끝 네 자리 `4775`)를 기본 카드로 만든다.
- 4775 카드의 기본 월 실적 목표는 300,000원이다.
- 실적 조건이 없는 카드는 목표를 0원으로 저장하지 않고 목표 없음으로 비활성화한다.
- 카드는 UUID로 관계를 식별하며, 자동 배정과 중복 등록 검증에는 카드사와 끝 네 자리의 정확한 조합을 사용한다.
- 같은 카드사와 끝 네 자리 조합의 중복 등록은 허용하지 않는다.
- 카드 이름, 카드사, 끝 네 자리와 실적 목표를 수정해도 기존 거래 관계는 유지한다.
- MVP 실적 산정 기간은 `Asia/Seoul` 기준 매월 1일 00:00 이상, 다음 달 1일 00:00 미만이다.
- MVP는 카드 한 장만 지원해도 되지만 데이터 구조는 여러 카드를 구분할 수 있어야 한다.

### 4.2 단축어용 거래 저장 기능

- 앱은 단축어에서 호출할 수 있는 `거래 문자 저장` 기능을 제공해야 한다.
- 필수 입력은 문자 원문 한 개다.
- 앱은 호출 시각을 수신 시각으로 함께 저장해야 한다.
- 앱 화면을 열지 않고 실행할 수 있어야 한다.
- 파싱에 실패하더라도 원문은 저장해야 한다.
- 저장 성공 또는 실패 결과를 단축어에 반환해야 한다.
- 같은 원문이 짧은 시간 안에 반복 전달되면 중복 저장하지 않아야 한다.

초기 중복 판정 규칙은 `정규화한 원문이 같고 수신 시각 차이가 10분 이내인 경우`로 한다. 서로 다른 실제 거래가 중복으로 판단될 가능성에 대비해 추후 사용자가 원문을 다시 가져올 수 있는 진단 수단을 둔다.

### 4.3 문자 파싱

승인 문자에서는 다음 값을 추출해야 한다.

- 거래 종류: 승인
- 카드 끝 네 자리
- 금액
- 거래 월/일 및 시각
- 가맹점명
- 통장 잔액(선택 값)

취소 문자에서는 다음 값을 추출해야 한다.

- 거래 종류: 승인취소
- 카드 끝 네 자리
- 취소 금액
- 취소 월/일
- 가맹점명

추가 규칙은 다음과 같다.

- 쉼표와 `원`, 마침표 등의 표현을 제거해 금액을 정수 원 단위로 저장한다.
- 연도가 없는 거래일은 `Asia/Seoul`의 수신일을 기준으로 미래가 아닌 가장 가까운 날짜로 추론한다. 파싱된 월/일이 수신 월/일보다 뒤면 전년, 같거나 앞이면 수신 연도를 사용한다.
- 파싱된 월/일이 수신일과 같으면 문자 시각이 수신 시각보다 조금 늦더라도 수신 연도를 유지한다.
- 취소 완료 시각이 없으므로 거래 시각은 비워두고 수신 시각을 목록 정렬에 사용한다.
- 파싱한 값과 문자 원문을 함께 보존한다.
- 알 수 없는 형식은 `파싱 실패` 상태로 저장해 사용자가 직접 입력할 수 있게 한다.
- 통장 잔액은 파싱할 수 있지만 기본 거래 목록과 현황 계산에는 사용하지 않는다.

### 4.4 거래 검토 및 수정

- 새로 수집한 거래의 초기 검토 상태는 `미확인`이어야 한다.
- 사용자는 다음 값을 확인하고 수정할 수 있어야 한다.
  - 카드
  - 승인 또는 취소
  - 금액
  - 거래 일시
  - 가맹점명
  - 실적 판정
  - 혜택 판정
  - 혜택 금액 또는 포인트
  - 메모
- 실적 판정 값은 `미확인`, `인정`, `제외`로 한다.
- 혜택 판정 값은 `미확인`, `받음`, `못 받음`, `대상 아님`으로 한다.
- 사용자 수정값은 자동 파싱을 다시 실행하더라도 덮어쓰지 않아야 한다.
- 사용자는 거래를 삭제할 수 있어야 한다.

### 4.5 승인취소 처리

- 취소 문자는 승인 거래와 별개의 거래로 저장하고 독립적으로 검토한다.
- MVP에서는 원승인 후보 검색과 승인–취소 연결을 제공하지 않는다.
- 실적 `인정`으로 확정한 승인은 해당 금액을 더하고, 실적 `인정`으로 확정한 취소는 해당 금액을 뺀다.
- 취소는 원승인 발생 기간이 아니라 취소 거래가 속한 실적 기간에서 차감한다.
- 기간의 실적 합계가 음수여도 0으로 보정하지 않는다. 남은 목표 금액 계산에도 음수 값을 그대로 사용해 그만큼 추가 실적이 필요하게 한다.
- 취소 금액은 혜택 합계를 자동으로 차감하거나 증가시키지 않는다. 혜택 합계는 사용자가 `받음`으로 확정한 혜택 값만 반영한다.

### 4.6 거래 목록

- 사용자는 최신 수신 순으로 거래를 볼 수 있어야 한다.
- 각 행에는 승인/취소, 가맹점, 금액, 거래 일시, 검토 상태를 표시한다.
- `미확인`, `파싱 실패`, `승인`, `취소` 조건으로 필터링할 수 있어야 한다.
- 미확인 거래 수를 쉽게 확인할 수 있어야 한다.

### 4.7 카드 현황

- 선택한 실적 기간에 대해 다음 값을 표시해야 한다.
  - 실적 인정 금액
  - 목표까지 남은 금액
  - 실적 제외 금액
  - 실적 미확인 금액
  - 받은 혜택 합계
  - 혜택 미확인 거래 수
- 현황 계산은 자동 추정이 아니라 사용자가 확정한 판정값을 기준으로 한다.
- 실적 `인정` 거래는 승인 금액을 양수, 취소 금액을 음수로 반영한다.
- 취소로 인해 실적 합계가 음수가 될 수 있으며 남은 목표 금액은 그 음수만큼 증가한다.
- 취소 금액은 혜택 합계에 자동 반영하지 않는다.

## 6. 기술 검증 항목

실제 iPhone에서 다음 경우를 각각 시험한다.

1. 앱이 화면에 열린 상태에서 승인 문자를 저장한다.
2. 앱이 백그라운드인 상태에서 승인 문자를 저장한다.
3. iPhone이 잠긴 상태에서 승인 문자를 저장한다.
4. 승인취소 문자를 저장한다.
5. 같은 입력을 연속 두 번 전달해 한 건만 남는지 확인한다.
6. 알 수 없는 문자를 전달해 원문이 `파싱 실패`로 남는지 확인한다.
7. 저장 실패 시 단축어에서 실패를 인지할 수 있는지 확인한다.

## 7. 인수 조건

제공된 세 문자에 대해 파서는 최소한 다음 결과를 만들어야 한다.

| 종류 | 카드 | 금액 | 거래 일시 | 가맹점 |
|---|---|---:|---|---|
| 승인 | 4775 | 2,500원 | 08/03 18:00 | 씨유(CU)삼성백암점 |
| 승인취소 | 4775 | 3,800원 | 08/03, 시각 미상 | 네이버페이 |
| 승인 | 4775 | 7,700원 | 08/03 16:40 | 네이버페이 |

다음 조건도 만족해야 한다.

- 세 입력 모두 원문이 보존된다.
- 파싱 실패가 앱 또는 자동화 전체 실패로 이어지지 않는다.
- 사용자가 모든 파싱 결과와 판정값을 수정할 수 있다.
- 수정한 사용자 판정이 카드 현황에 반영된다.
- 실적 `인정` 취소는 취소 발생 기간의 실적에서 차감되고 결과가 음수여도 보존된다.
- 취소 금액만으로 혜택 합계가 바뀌지 않는다.
- 외부 서버나 로그인 없이 동작한다.

## 8. MVP 제외 범위

- 카드 약관에 따른 실적 및 혜택 자동 확정
- 네이버페이 등 간편결제의 실제 하위 가맹점 자동 식별
- 은행 계좌 잔액 관리
- 카드사 서버, 마이데이터 및 오픈뱅킹 연동
- 회원가입, 로그인, 다중 사용자 및 기기 간 동기화
- 두 번째 카드사의 문자 형식 지원
- 취소 원승인 후보 검색과 승인–취소 연결

## 9. 구현 전에 남은 결정

다음 항목은 기술 실험 또는 사용자 확인 후 확정한다.

1. 혜택을 현금 금액만 기록할지, 포인트 등 여러 단위를 지원할지 여부
2. 로컬 저장 자료의 백업 및 복구 방식

통장 잔액이 포함된 원문은 기기에 보존하되 기본 화면, 집계와 로그에서는 숨기는 것으로 확정했다. 자세한 저장·노출 경계는 `ARCHITECTURE.md`와 ADR-0004를 따른다.
