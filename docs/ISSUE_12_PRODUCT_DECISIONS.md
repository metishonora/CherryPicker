# Issue #12 제품 결정 기록

- 이슈: `MG+S 하나카드 정의와 수집 연동`
- 기록일: 2026-08-19
- 상태: 승인 파서, 안전한 카드 배정, 집계·API·제품 UI 구현 완료
- 기준: 2026-08-19 사용자와 확정한 제품 결정

## 목적

`MG+S 하나카드`를 기존 카드와 구분되는 독립 카드 종류로 추가한다.
카드 정의는 문자 식별·파싱 규칙뿐 아니라 전월 실적 구간, 실적 제외
정책과 확인된 혜택 정책을 함께 소유한다. 보유 카드는 이 정의를 참조한다.

이 문서는 현재까지 확정한 실적·혜택 정책과 승인 문자 형식을 기록한다.
승인취소 형식은 아직 확인하지 않았으므로 해당 파서 요구사항은 확정하지
않는다.

## 승인된 UI 프로토타입

2026-08-19에 `Prototypes/Issue12/index.html`의 대시보드와 카드 설정
프로토타입을 제품 UI 구현 기준선으로 승인했다.

- 대시보드는 이번 달 누적 인정 실적과 카드 정책에서 자동 선택한 다음 실적
  구간 목표, 남은 금액과 진행도를 표시한다.
- MG+S 혜택은 남은 통합혜택한도, 이번 달 받은 혜택 합계와 하나의 통합
  진행도로 표시한다.
- 혜택별 받은 금액에는 각 혜택 조건을 함께 표시한다.
- 이번 달 혜택한도를 정한 직전 월 최종 실적과 구간 판정 카드는 대시보드에
  표시하지 않는다. 현재 월의 다음 실적 구간 목표는 별도로 표시한다.
- 공통 할인 제외 대상은 혜택 패널에서 기본으로 접어 표시한다.
- 카드 설정에서 단일 실적 목표를 제거하고 직전 월 실적 오프셋과 이번 달
  혜택별 오프셋을 관리한다.
- 프로토타입 전용 상태 선택기는 제품 UI에 포함하지 않는다.

2026-08-19 후속 프로토타입 승인으로 실적 목표 표시는 다음과 같이 확정했다.

- 보유 카드에 사용자가 입력하는 목표는 다시 만들지 않는다.
- MG+S는 300,000원, 600,000원, 1,000,000원 중 현재 실적보다 높은 다음
  구간을 자동 목표로 사용한다.
- 최고 구간에 도달하면 1,000,000원을 목표로 유지하고 달성 상태를 표시한다.
- 기존 MG 더나은 체크카드는 300,000원 단일 실적 조건을 자동 목표로 사용한다.
- 대시보드와 거래 검토는 같은 자동 목표, 남은 금액과 진행도를 표시한다.
- 거래 검토에서 실적 인정·제외를 바꾸어 경계를 넘으면 목표도 다음 구간으로
  즉시 전환한다.

다음 외부 동작을 HTTP 블랙박스 테스트로 고정했다.

- 카드와 대시보드 계약에서 편집 가능한 단일 실적 목표를 제거한다.
- iPhone 메시지 자동화의 발신자에 `1599-9000`과 `1800-1111`을 함께
  등록해 두 카드 문자를 같은 Outbox 수집 흐름으로 전달한다.
- 직전 월의 검토 확정 인정 실적과 같은 월의 실적 오프셋만 이번 달
  혜택한도를 결정한다.
- 300,000원, 600,000원과 1,000,000원 경계를 각각 상위 구간에 포함한다.
- 세 혜택의 계산 금액이 하나의 통합혜택한도를 함께 소진한다.
- 실적·혜택 오프셋은 카드와 월 사이에서 섞이지 않는다.
- 기존 MG 더나은 체크카드는 편집 가능한 목표를 제거하되 300,000원 고정
  실적 조건과 혜택별 월 한도를 유지한다.

## 현재 구현 상태

2026-08-19에 다음 범위를 구현했다.

- 안정적인 카드 종류 코드 `hana.mg-plus-s`
- MG+S 하나카드와 기존 MG 더나은 체크카드의 발신자 메타데이터
- `MG+ 하나` 본문 서명과 개인정보 제거 승인 fixture 기반 파서
- MG+S, 원더카드와 MG 더나은 체크카드 본문의 상호 배타적 routing
- 보유 카드 생성 HTTP API와 SQLite 저장
- `A*C*` 마스킹 식별자가 하나의 보유 카드와 일치할 때만 카드 배정
- 미지원·불명확·중복 매칭 문자의 미배정 보존과 안전한 HTTP 조회
- 미배정 거래를 `카드 미배정`으로 표시하고 편집을 막는 기본 웹 안전 처리
- 카드 정의가 소유하는 MG+S 세 혜택과 13개 공통 할인 제외 대상
- 직전 월 최종 실적에 따른 이번 달 통합혜택한도 계산
- 카드·월별 실적 및 혜택 오프셋
- 편집 가능한 단일 실적 목표를 제거한 API와 제품 UI
- 카드 정책의 고정 실적 구간에서 다음 목표와 남은 금액을 파생하는 API
- 대시보드와 거래 검토의 자동 실적 목표 진행도
- 승인된 프로토타입을 반영한 통합혜택 대시보드와 카드 설정

승인취소 문자의 확인된 형식이 없으므로 MG+S 승인취소 파서만 후속 작업으로
남는다.

## 전월 실적과 이번 달 통합혜택한도

전월 실적 구간에 따라 이번 달에 사용할 수 있는 통합혜택한도를 결정한다.

| 전월 최종 실적 | 이번 달 통합혜택한도 |
| --- | ---: |
| 300,000원 미만 | 0원 |
| 300,000원 이상 600,000원 미만 | 15,000원 |
| 600,000원 이상 1,000,000원 미만 | 30,000원 |
| 1,000,000원 이상 | 60,000원 |

경계값인 300,000원, 600,000원과 1,000,000원은 각각 상위 구간에
포함한다. 모든 혜택은 별도 한도나 횟수 제한 없이 같은 월
통합혜택한도를 함께 소진한다.

이번 달 통합혜택한도는 다음 값으로 결정한다.

```text
직전 월의 검토 확정 인정 실적
+ 선택한 카드의 직전 월 실적 오프셋
= 직전 월 최종 실적
-> 카드 정의의 실적 구간 판정
-> 이번 달 통합혜택한도
```

직전 월 실적이 없으면 0원으로 간주한다. 필요한 경우 사용자가 직전 월
실적 오프셋을 지정해 카드사 현황에 맞춘다.

## 문자 식별과 승인 파싱

iPhone의 `CherryPicker Outbox` 단축어는 카드 종류를 판정하지 않는다.
개인용 메시지 자동화가 두 발신자 중 하나에서 받은 문자 원문을 단축어 입력으로
전달하고, 서버가 발신자 메타데이터와 본문 서명으로 카드 종류를 구분한다.
개인용 자동화는 기기별 설정이므로 실제 iPhone에서 두 발신자를 모두 추가해야
하며 다른 Apple 기기에서 대신 수정할 수 없다.

2026-08-19에 확인한 실제 승인 문자의 원문은 이 문서나 fixture에 보존하지
않는다. 개인정보와 실제 거래값을 대체한 다음 구조만 회귀 fixture로
사용한다.

```text
[Web발신]
MG+ 하나1*2*승인 홍*동 12,340원 일시불 01/15 12:34 합성상점 누적123,456원
```

MG+S 하나카드는 본문의 `MG+ 하나` 서명으로 식별한다. `하나` 뒤에는
마스킹된 카드 식별자가 오고 바로 `승인`이 이어진다. 승인 파서는 다음
값을 추출한다.

- 카드 종류: `MG+S 하나카드`
- 마스킹된 카드 식별자
- 거래 종류: 승인
- 승인금액
- 할부 표기
- 거래 월·일과 시·분
- 가맹점

사용자 이름과 누적 이용금액은 canonical 거래 필드로 사용하지 않으며 기본
UI, 오류와 로그에 노출하지 않는다.

### 마스킹 카드 식별자와 보유 카드 관계

확인된 두 하나카드 사례에서 문자에 표시되는 식별자는 보유 카드 끝 네
자리의 첫 번째와 세 번째 숫자만 남기고 두 번째와 네 번째 숫자를 `*`로
가린 값이다.

```text
보유 카드 끝 네 자리: ABCD
문자 식별자:          A*C*
```

파서는 문자만으로 실제 끝 네 자리를 복원하지 않는다. 먼저 본문 서명으로
카드 종류를 식별하고, 저장된 같은 카드 종류의 보유 카드마다 끝 네 자리로
`A*C*` 서명을 계산해 문자 식별자와 비교한다.

- 카드 종류와 마스킹 서명이 모두 일치하는 보유 카드가 하나일 때만 해당
  카드에 배정한다.
- 같은 카드 종류에서 같은 마스킹 서명을 가진 보유 카드가 둘 이상이면
  임의로 선택하지 않고 미배정 검토 상태로 남긴다.
- 본문 서명은 맞지만 저장된 보유 카드와 마스킹 서명이 일치하지 않아도
  다른 카드에 추측 배정하지 않는다.
- 실제 끝 네 자리는 카드 종류 정의나 합성 fixture가 아니라 보유 카드
  instance 데이터로 저장한다.

따라서 Issue #12의 `카드 끝 네 자리 파싱`은 하나카드 문자에 대해서는
`마스킹 식별자 파싱 후 보유 카드 instance와 일치 확인`으로 구체화한다.

이후 추가할 원더카드의 알려진 승인 형식은 `MG+ ` 접두사 없이 `하나`로
시작한다. 다음과 같은 개인정보 제거 합성 fixture를 MG+S 하나카드의
오인 방지 회귀 사례로 사용한다.

```text
[Web발신]
하나9*8*승인 홍*동 5,200원 일시불 01/14 17:06 합성멤버십 누적98,765원
```

- `MG+ 하나...승인` 형식만 MG+S 하나카드로 식별한다.
- `하나...승인` 형식을 MG+S 하나카드로 추측 배정하지 않는다.
- 알려진 형식과 본문 서명이 맞지 않으면 파싱 실패 또는 미배정 검토
  상태로 원문을 보존한다.
- 원더카드 자체의 카드 정의와 파서는 후속 작업에서 구현한다.

### 세 카드 형식의 상호 배타적 식별

카드 식별은 발신자만으로 결정하지 않고 각 카드 정의의 긍정적인 본문
서명을 함께 사용한다. 현재 확인된 승인 본문 서명은 다음과 같다.

| 카드 종류 | 발신자 | 승인 본문 서명 |
| --- | --- | --- |
| MG 더나은 체크카드 | `1599-9000` | `MG...카드(숫자 네 자리)...체크승인` |
| MG+S 하나카드 | `1800-1111` | `MG+ 하나...마스킹 카드 식별자...승인` |
| 원더카드 | `1800-1111` | `하나...마스킹 카드 식별자...승인`, `MG+ ` 접두사 없음 |

MG+S 하나카드와 원더카드는 같은 발신자를 공유하므로 `1800-1111`만으로
카드 종류를 결정할 수 없다. 발신자를 먼저 확인한 뒤 하나카드 두 종류의
상호 배타적인 본문 서명을 적용한다. `[Web발신]` 표시는 발신자 식별값으로
사용하지 않는다.

MG 더나은 체크카드의 기존 파서는 `체크승인` 표식과
`MG...카드(숫자 네 자리)` 형식을 요구한다. 따라서 하나카드 두 형식을
`체크승인`이라는 부분 일치나 카드 번호만으로 기존 카드에 배정해서는 안
된다. 반대로 원더카드의 일반적인 `하나` 서명은 `MG+ 하나`를 포함하는
문자를 먼저 가져가면 안 된다.

식별과 파서 테스트는 다음 상호 배타성을 보장해야 한다.

- MG+S 정의는 MG+S 승인 fixture만 식별하고 원더카드와 MG 더나은
  체크카드 fixture를 거부한다.
- MG 더나은 체크카드 정의는 기존 승인 fixture만 식별하고 하나카드 두
  fixture를 거부한다.
- 향후 원더카드 정의는 원더카드 fixture만 식별하고 `MG+ 하나` 및 MG
  더나은 체크카드 fixture를 거부한다.
- 카드 정의 registry를 통과한 알려진 문자는 정확히 하나의 카드 종류와
  매칭된다.
- 본문 형식이 맞더라도 해당 카드 정의의 발신자와 일치하지 않으면 카드에
  배정하지 않는다.
- `MG+`, `하나`, `승인` 중 일부만 있거나 서로 충돌하는 문자는 어느
  카드에도 추측 배정하지 않는다.

승인취소 실제 형식은 아직 확인하지 못했다. MG+S 하나카드 승인취소 파서는
형식을 확인한 뒤 개인정보 제거 fixture와 함께 후속 구현한다. 그 전에는
승인 형식에서 취소 형식을 추측하지 않으며, 알 수 없는 취소 문자는 다른
카드에 배정하지 않고 검토 가능한 상태로 보존한다.

## 카드 설정과 오프셋

사용자가 임의로 지정하는 단일 월 실적 목표는 모든 카드에서 제거한다.
카드에는 여러 실적 구간이 있을 수 있으므로 하나의 목표값을 카드 instance
설정으로 소유하지 않는다.

- 카드 설정에서 월 실적 목표 입력을 제거한다.
- 저장된 사용자 목표값은 집계에 사용하지 않는다.
- 직전 월 실적 오프셋을 선택한 카드별로 조회·수정한다.
- 실적 오프셋은 실적이 발생한 월을 기준으로 카드·월별로 저장한다.
- 기존 #10 결정에 따라 양수와 음수 오프셋을 허용하고 값이 없으면 0으로
  취급한다.
- 혜택별 오프셋은 선택한 카드·현재 혜택 월·혜택 ID별로 유지한다.
- 카드나 월이 다르면 실적 및 혜택 오프셋이 서로 섞이지 않는다.

기존에 저장된 사용자 실적 목표값은 데이터 호환성을 위해 물리적으로
보존하지만 도메인·API·화면에서는 읽거나 수정하지 않는다. 다른 사용자
수정값과 거래 원문도 그대로 보존한다.

## 대시보드 표시

현재 월 중심의 대시보드 구성은 유지하되 사용자 설정 목표가 아닌 카드 정책의
고정 실적 구간을 목표 표시에 사용한다.

- 이번 달 누적 인정 실적과 자동 선택한 목표를 함께 표시한다.
- 다음 실적 구간까지 남은 금액과 목표 진행률을 표시한다.
- 최고 실적 구간에서는 최고 구간 달성 상태를 표시한다.
- 거래 검토에서도 인정·제외 선택을 반영한 같은 목표와 진행률을 표시한다.
- 다음 달 예상 혜택한도는 표시하지 않는다.
- 직전 월 최종 실적으로 정해진 이번 달 통합혜택한도를 표시한다.
- 이번 달 혜택 사용액과 남은 통합혜택한도를 표시한다.
- 거래 또는 직전 월 오프셋이 바뀌면 영향을 받는 카드와 혜택 월만 다시
  계산한다.

## 기존 카드와 관련 요구사항에 미치는 영향

편집 가능한 실적 목표 제거, 카드 정책 기반 자동 목표와 전월 실적 기반 한도
계산 모델은 MG+S 하나카드뿐 아니라 기존 지원 카드에도 적용한다. 카드별 실적
구간과 혜택 정책은 각 카드 정의가 소유해야 한다.

이 결정은 다음 기존 설명을 후속 구현과 함께 수정해야 한다.

- Issue #12의 `기존 카드 정의의 정책 변경` 제외 범위
- Issue #10의 `이번 달 실적 오프셋`, 자동 목표와 남은 금액 계산
- `PRODUCT_ARCHITECTURE.md`의 기본·사용자 실적 목표 소유권
- `PRODUCT_UI_PRINCIPLES.md`의 실적 목표 설정 UI
- MVP 및 아키텍처 문서의 사용자 수정 실적 목표 설명

현재 구현을 설명하는 문서는 코드 변경 전까지 그대로 두고, 이 문서를
승인된 후속 요구사항으로 사용한다.

## 아직 확인할 사항

- 혜택과 실적 조건을 뒷받침하는 공식 자료의 문서명, URL 또는 확인일
- MG+S 하나카드의 승인취소 문자 형식
- 기존 지원 카드별 실적 구간과 구간별 혜택한도
- 기존 저장 목표값을 장기적으로 제거할지에 관한 migration 정책

실제 카드 문자 사용은 별도의 명시적 승인 뒤에 진행한다. 그 전에는
개인정보를 제거한 합성 fixture만 사용하며, 실제 원문을 문서, GitHub,
fixture, 기본 UI 또는 로그에 기록하지 않는다.
