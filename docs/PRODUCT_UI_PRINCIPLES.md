# CherryPicker 제품 UI 원칙

- 상태: Issue #5 프로토타입 기준
- 검토일: 2026-08-17
- 적용 범위: 거래 목록, 거래 검토, 카드 설정을 포함한 로컬 웹 제품 UI

## 목적

CherryPicker의 UI는 카드 거래를 빠르게 찾고, 판정을 이해하고, 사용자의
의도대로 검토 결과를 저장하게 해야 한다. 이 문서는 토스의 공개 디자인
원칙과 Toss Design System(TDS)의 정보 구성 방식을 참고하되 CherryPicker의
제품 요구에 맞게 재해석한 기준이다.

이 문서는 토스 브랜드, TDS 패키지, 토스 전용 글꼴이나 그래픽 자산을
사용하라는 의미가 아니다. 프로토타입 승인은 제품 기술 스택도 결정하지
않는다.

## 우선순위

UI 판단이 충돌하면 다음 순서로 결정한다.

1. 최신 사용자 결정
2. Issue #5의 현재 정책 결정과 완료 조건
3. 승인된 프로토타입
4. 이 문서의 공통 원칙
5. 외부 참고 사례

## 공통 원칙

### 1. 한 화면은 한 가지 일을 선명하게 돕는다

- 카드 미선택 상태의 주된 일은 모든 카드의 미확인 거래를 검토하는 것이다.
- 카드 선택 상태의 주된 일은 해당 카드의 실적·혜택 현황과 거래를 관리하는
  것이다.
- 거래 상세의 주된 일은 거래 정보를 확인하고 판정을 저장하는 것이다.
- 카드 설정의 주된 일은 선택한 카드의 정보를 수정하는 것이다.
- 카드 대시보드에는 실적과 혜택 현황 외의 부가 지표를 추가하지 않는다.

토스의 `One thing per one page` 원칙을 참고한다.

### 2. 사용자가 익숙한 구조와 명시적인 문구를 우선한다

- 목록, 라디오, 체크박스, 스위치와 버튼은 웹의 기본 동작을 유지한다.
- 내부 모델명보다 `미확인`, `실적 인정`, `선택한 혜택 없음`,
  `이 거래를 집계하지 않음`처럼 결과를 바로 이해할 수 있는 문구를 쓴다.
- 색상, 아이콘이나 위치만으로 상태를 전달하지 않는다.
- 되돌릴 수 있는 동작과 집계 효과를 동작 근처에서 설명한다.

### 3. 거래는 카드 묶음이 아니라 읽기 쉬운 목록 행으로 보여준다

- 한 거래 행은 `가맹점과 보조 정보`를 왼쪽, `금액과 상태`를 오른쪽에 둔다.
- 통합 미확인 거래에서는 각 행에 카드 이름과 끝 네 자리를 함께 표시한다.
- 카드를 선택한 뒤의 거래 목록에서는 상단 카드 문맥을 사용하고 행마다 카드
  이름을 반복하지 않는다.
- 거래 종류, 거래 일시와 수신 시각은 주 정보보다 낮은 위계로 표현한다.
- 반복되는 행은 개별 카드 테두리나 그림자 대신 충분한 여백과 구분선으로
  나눈다.
- 행 전체를 선택할 수 있게 하되 키보드와 보조 기술에서도 같은 동작을
  제공한다.

TDS `ListRow`의 left, contents, right 구조를 참고한다.

### 4. 중립 색상을 기본으로 하고 강조색은 한정해서 사용한다

- 페이지와 입력 배경은 차가운 흰색·회색 계열을 사용한다.
- 기본 텍스트, 보조 텍스트와 구분선의 명암 단계로 정보 위계를 만든다.
- CherryPicker 강조색은 현재 선택과 주요 저장 동작에만 사용한다.
- 상태 배지는 낮은 채도의 배경과 상태 문구를 함께 사용한다.
- 오류와 위험 상태의 색을 일반 강조나 장식에 사용하지 않는다.

프로토타입의 밝은 화면 기준 중립 단계는 다음 TDS 공개 색상을 참고한다.

- 주 텍스트: `grey900` (`#191f28`)
- 보조 텍스트: `grey700` (`#4e5968`)
- 약한 텍스트: `grey500` (`#8b95a1`)
- 구분선: `grey200` (`#e5e8eb`)
- 보조 배경: `grey100` (`#f2f4f6`)

이 값은 참고 기준이며 TDS 색상 패키지에 의존하지 않는다. 다크 모드에서는
동일한 의미와 대비를 보존하는 CherryPicker 전용 토큰을 사용한다.

### 5. 상태는 의미와 강도를 일관되게 표현한다

- `미확인`: 주의가 필요하지만 오류는 아닌 약한 주의 상태
- `확인`: 완료를 나타내는 약한 성공 상태
- `파싱 실패`: 사용자의 확인이 필요한 약한 오류 상태
- `집계 제외`: 거래는 남아 있지만 집계되지 않는 중립적 제외 상태
- `취소`: 금액 부호와 `취소` 문구를 함께 표시

강한 채움 배지는 즉시 대응이 필요한 상태에만 사용하고, 목록의 일반 상태는
낮은 채도의 배지로 표현한다.

### 6. 거래 사실과 검토 입력을 분리한다

- 카드, 승인·취소 종류, 금액, 가맹점과 거래 일시는 상세 상단의 읽기 전용
  거래 요약으로 보여준다.
- 거래 상세는 토스의 실제 상세 내역 화면처럼 금액을 가장 크게, 카드와
  가맹점·거래 일시를 그다음 위계로 넉넉한 여백과 함께 보여준다.
- 읽기 전용 정보에는 연필 아이콘, 꺾쇠나 입력 형태처럼 수정 가능해 보이는
  시각적 단서를 두지 않는다.
- 거래 사실은 검토 화면에서 수정 입력이나 초기화 동작으로 제공하지 않는다.
- 거래 요약 아래에 실적, 혜택, 메모와 집계 제외를 검토 입력으로 둔다.
- 모든 검토 입력에는 계속 보이는 레이블을 둔다.
- 선택지는 결과가 분명한 문구로 제공한다.
- 실적 진행도와 혜택 미선택 의미를 설명하는 보조 문구는 반복 표시하지 않는다.
- 오류는 문제가 발생한 필드나 저장 동작 근처에서 해결 방법과 함께 보여준다.
- 실적 `인정 / 제외` 선택은 현재 카드의 월 실적 합계와 목표 달성 진행도에
  즉시 반영한다.
- 혜택을 하나도 선택하지 않으면 별도 선택지 없이 `해당 혜택 없음`으로
  해석한다.
- 혜택 선택 항목은 `커피 20% 할인캐시백`처럼 대상과 혜택률을 한 문장으로
  표시하고, 바로 아래에 대상 가맹점·최소 결제금액·전월 실적 조건·월 한도와
  해당 혜택만의 제외 조건을 짧게 표시한다.
- 선택한 혜택에는 `받은 혜택 / 총 받을 수 있는 혜택`과 가로 진행도를 표시한다.

### 7. 화면마다 주요 동작은 하나만 강하게 표시한다

- 거래 상세의 주요 동작은 `저장하고 확인`이다.
- `취소`는 약한 보조 버튼으로 같은 동작 영역에 둔다.
- 집계 제외는 저장 버튼과 경쟁하는 별도 위험 CTA가 아니라 명시적인 거래
  상태 선택으로 제공한다.
- 긴 화면에서도 최종 동작의 위치와 의미를 예측할 수 있어야 한다.

TDS `BottomCTA`의 단일·이중 CTA 구조를 참고한다.

### 8. 모바일 우선으로 만들되 데스크톱에서도 웹페이지답게 보인다

- 최소 320px 폭에서 가로 스크롤 없이 모든 핵심 흐름을 완료할 수 있어야 한다.
- iPhone Safari를 우선 검토하고 736px 이상의 데스크톱 폭도 확인한다.
- 넓은 화면에서도 모바일 기기 프레임을 흉내 내지 않는다.
- 콘텐츠의 읽기 폭을 제한하고, 같은 정보 위계와 상호작용을 유지한다.
- 단순히 공간을 채우기 위해 거래 행을 카드 그리드로 바꾸지 않는다.

### 9. 접근성과 안전한 기본값을 시각 설계에 포함한다

- 네이티브 HTML 컨트롤과 의미 있는 제목 구조를 사용한다.
- 키보드 포커스, 200% 글자 확대, VoiceOver 레이블과 충분한 대비를 보장한다.
- 원문과 파싱 진단은 접힌 보조 영역에서만 보여준다.
- 프로토타입에는 합성 fixture만 사용한다.
- 입력값과 원문을 출력할 때 HTML escape하는 제품 요구는 시각 구현에서도
  유지한다.

## 화면별 적용

### 통합 미확인 거래

- 첫 화면에서는 카드를 선택하지 않은 상태로 모든 카드의 미확인 거래와 전체
  미확인 건수를 표시한다.
- 각 거래 행에서 어느 카드의 거래인지 바로 구분할 수 있어야 한다.
- 수신 시각 역순의 한 열 목록을 기본으로 한다.
- 빈 결과는 확인할 거래가 없다는 문장으로 구분한다.

### 카드 선택과 대시보드

- 기존 카드 인스턴스를 상단 카드 선택기로 선택한다.
- 카드를 선택하면 해당 카드의 대시보드로 이동하고 `대시보드 / 거래 / 카드
  설정` 문맥 메뉴를 표시한다.
- 현재 탭은 강조색 글자와 옅은 강조 배경을 함께 사용해 다른 탭과 구분하고,
  의미상 `aria-current="page"`로 표시한다. 한 번에 하나의 탭만 현재 상태여야
  한다.
- 대시보드에는 이번 달 실적 합계와 목표 진행도, 각 혜택의 받은 금액과 최대
  제공 금액 진행도를 표시한다.
- 실적 목표는 카드 정책의 다음 실적 구간을 자동으로 사용한다. 다음 구간까지
  남은 금액을 표시하고 최고 구간에서는 달성 상태를 표시한다.
- `미확인 거래`로 돌아가면 카드 선택을 해제하고 다시 통합 목록을 보여준다.

### 카드 거래

- 선택한 카드의 거래만 표시한다.
- `전체 / 승인 / 취소 / 집계 제외` 필터를 제공한다.
- 빈 결과는 현재 필터에 맞는 거래가 없다는 문장으로 구분한다.

### 거래 검토

- 카드, 승인·취소 종류, 금액, 가맹점과 거래 일시는 상단에 큰 읽기 전용
  요약으로 배치한다.
- 읽기 전용 거래 요약 아래에 검토 판정, 집계 제외, 보조 정보 순으로 배치한다.
- 실적은 `인정 / 제외` 중 하나를 선택한다.
- 실적 선택 직후 현재 카드의 반영 후 월 실적 합계와 목표 대비 가로 진행도를
  표시한다. 승인은 더하고 취소는 차감하며, 실적 제외는 합계를 바꾸지 않는다.
- 거래 검토의 목표와 남은 금액은 대시보드와 같은 카드 정책으로 다시 계산한다.
  거래 반영으로 구간 경계를 넘으면 즉시 다음 구간으로 목표를 전환한다.
- 혜택은 0개 이상의 혜택을 복수 선택한다. 선택이 0개이면 `해당 혜택 없음`으로
  저장하며 별도의 없음 선택지는 제공하지 않는다.
- 선택한 각 혜택 바로 아래에 이번 거래 반영 후 받은 혜택 금액, 해당 혜택의
  최대 제공 금액과 가로 진행도를 보여준다. 승인은 혜택 금액을 더하고 취소는
  차감한다.
- 취소 거래도 원승인 매칭 없이 같은 검토 구조를 사용한다.
- `집계 제외`, `보조 정보` 같은 대분류 제목과 집계 제외 설명 문구는 표시하지
  않는다. 동작 레이블과 접힌 원문 항목만 남긴다.
- `이 거래를 집계하지 않음`을 선택하면 검토 섹션 전체를 흐리게 표시하고 입력을
  비활성화한다. 선택을 해제하면 기존 입력 상태를 보존한 채 다시 활성화한다.
- 원문과 파싱 정보는 기본으로 접어 둔다.
- 모바일 Safari에서 메모 입력에 포커스해도 화면이 확대되지 않게 입력 글자 크기를
  최소 16px로 유지한다.

### 카드 설정

- 선택한 카드 인스턴스만 조회·수정한다.
- 범용 카드 추가·삭제 UI를 제공하지 않는다.
- 편집 가능한 월 실적 목표는 보여주지 않는다.
- 직전 월 실적 오프셋과 이번 달 혜택별 오프셋을 서로 다른 월 문맥으로
  보여준다.
- 모바일 Safari에서 카드 설정의 모든 입력 필드에 포커스해도 화면이 확대되지
  않게 입력 글자 크기를 최소 16px로 유지한다.

## 프로토타입 검토 체크리스트

- 320px, iPhone 폭과 736px 이상에서 내용이 겹치거나 잘리지 않는다.
- 카드 미선택 상태에서 여러 카드의 미확인 거래가 함께 보인다.
- 카드를 선택하면 해당 카드 대시보드와 문맥 메뉴가 나타난다.
- 탭을 전환하면 선택한 탭 하나만 글자와 배경으로 강조되고
  `aria-current="page"`를 갖는다.
- 선택 카드의 거래 필터를 바꾸면 해당 카드의 승인·취소·집계 제외 거래만
  남는다.
- `미확인 거래`로 돌아가면 카드 선택과 카드 문맥 메뉴가 해제된다.
- 거래 행을 선택해 상세로 이동하고 목록으로 돌아올 수 있다.
- 거래 상세 상단의 카드, 종류, 금액, 가맹점과 거래 일시가 읽기 전용이다.
- 실적 인정·제외를 바꾸면 반영 후 월 실적 합계가 즉시 바뀐다.
- 실적 판정을 완료하면 혜택을 하나도 선택하지 않은 상태로도 확인 저장할 수
  있고, 이는 `해당 혜택 없음`으로 해석된다.
- 혜택을 선택하면 해당 항목 안에 받은 혜택 금액과 최대 제공 금액의 가로
  진행도가 나타나고, 선택을 해제하면 사라진다.
- 집계 제외를 선택하면 검토 섹션이 흐려지고 해당 입력이 비활성화되며, 해제하면
  다시 활성화된다.
- 모바일에서 메모 입력에 포커스해도 화면 배율이 변하지 않는다.
- 모바일에서 카드 설정의 각 입력 필드에 포커스해도 화면 배율이 변하지 않는다.
- `이 거래를 집계하지 않음`이 목록과 상세에서 명시적으로 보인다.
- 카드 설정에서 직전 월 실적 조정, 이번 달 혜택 조정과 저장 피드백을
  확인할 수 있다.
- 모든 상태가 색상 외의 문구로도 구분된다.
