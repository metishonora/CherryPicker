# CherryPicker 로컬 웹 MVP

- 상태: 현재 제품 목표
- 지원 카드: MG 더나은 체크카드, MG+S 하나카드
- 기준 아키텍처: [로컬 웹 제품 아키텍처](PRODUCT_ARCHITECTURE.md)

## 사용자가 얻는 결과

카드 문자가 iPhone에서 먼저 유실 없이 보존되고, Mac에 도착한 거래를
브라우저에서 확인·수정한 뒤 카드 실적과 혜택 현황을 볼 수 있다.

## 제품 단계

### #8 최소 제품

- Mac 로컬 서버를 제품 이름과 경로로 실행한다.
- 합성 Outbox 이벤트를 SQLite에 저장하고 파싱한다.
- 브라우저에서 거래와 파싱 상태를 확인한다.
- 재시작 후 보존과 동일 eventId 재전송 멱등성을 확인한다.
- localhost, tailnet-only와 exact-login 경계를 유지한다.

### #5 거래 검토

- 카드 설정과 거래 목록을 제공한다.
- 실제 화면을 보며 필요한 수정·판정 필드를 확정한다.
- 사용자 수정값을 저장하고 재파싱보다 우선한다.

### #9 실제 수집

- 실제 승인·승인취소 문자를 iPhone 로컬 Outbox에 먼저 저장한다.
- Mac이 일시적으로 꺼져 있어도 파일을 보존하고 연결 복구 후 재전송한다.

### #12 두 번째 카드 수집

- iPhone 메시지 자동화가 `1599-9000`과 `1800-1111` 발신자를 모두 받는다.
- 서버가 본문 서명으로 MG 더나은 체크카드와 MG+S 하나카드를 구분한다.
- MG+S 승인취소는 실제 형식을 확인한 뒤 추가한다.

### #4 현황

- 사용자가 확정한 실적·혜택 판정으로 현황을 계산한다.
- 취소는 취소 발생 기간의 독립 음수 거래로 반영한다.

## MVP 전체 성공 조건

- 실제 문자 원문이 서버 확인 전 유실되지 않는다.
- 파싱 실패 거래도 검토 대상으로 남는다.
- 사용자가 파싱값과 판정을 확인하고 수정할 수 있다.
- 사용자 판정으로 카드 현황을 확인할 수 있다.
- 공개 인터넷 서비스나 별도 사용자 계정 없이 본인만 접근한다.

## 제외 범위

- 기존 SwiftData 이전
- 네이티브 iOS 앱
- 공개 호스팅, 회원가입과 다중 사용자
- 카드 정책에 따른 완전 자동 판정
- 두 번째 카드사
- 자동 백업과 장기 운영 정책

세부 데이터 구조와 화면 정책은 해당 단계의 실제 구현을 확인하면서 정한다.
