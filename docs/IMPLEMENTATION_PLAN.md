## 1. 이번 구현의 목표

이번 단계에서는 완성된 카드 관리 앱을 만들지 않는다. 다음 경로가 실제 iPhone에서 동작하는지 최소한의 코드로 검증한다.

```text
MG 승인 또는 취소 문자
  → iPhone 개인용 자동화
  → CherryPicker App Intent
  → 로컬 원문 저장
  → MG 문자 파싱
  → 앱의 수집 내역에서 결과 확인
```

기술 검증이 끝나면 UI와 집계 기능을 확장해도 되는지 판단할 수 있어야 한다.

## 2. 권장 기술 선택

| 항목 | 권장 선택 | 이유 |
|---|---|---|
| UI | SwiftUI | 개인용 iPhone 앱의 작은 화면 범위에 적합하다. |
| 최소 지원 버전 | iOS 27 | 사용자의 실제 기기가 iOS 27이며 이전 버전 지원이 필요하지 않다. |
| 로컬 저장 | SwiftData | 별도 서버 없이 앱과 App Intent가 같은 모델을 사용할 수 있다. |
| 단축어 연동 | App Intents | 단축어에서 문자열을 받아 백그라운드 저장 기능을 제공한다. |
| 파서 | Foundation 기반 순수 Swift 타입 | iOS UI나 저장소 없이 단위 테스트할 수 있다. |
| 테스트 | Swift Testing 또는 XCTest | 제공된 실제 문자 세 건을 회귀 테스트로 고정한다. |
| 외부 의존성 | 사용하지 않음 | 첫 기술 검증의 설치 및 실패 변수를 줄인다. |

저장소와 파서는 프로토콜로 분리한다. App Intent, 앱 화면, 테스트가 같은 저장 및 파싱 규칙을 재사용하되 SwiftUI 화면이 핵심 로직을 소유하지 않게 한다.

## 3. 현재 개발 환경과 선행 조건

현재 환경에는 Xcode 27 beta 4, iOS 27 SDK 및 iOS 27 시뮬레이터가 준비되어 있다. 명령행 빌드는 `DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer`를 지정해 실행한다.

확인 결과:

- 코어 XCTest 7건 통과
- SwiftData 저장소 XCTest 5건 통과
- iPhone 17 Pro 시뮬레이터 설치 및 실행 통과
- 실제 iPhone 개발자 모드, 기기 등록, 자동 서명 및 앱 설치 완료

실기기 검증에 사용한 준비 항목은 다음과 같다.

1. 단축어의 메시지 개인용 자동화를 구성한다.
2. 실제 승인 및 취소 문자를 수신해 저장 결과를 확인한다.
3. 백그라운드 및 잠금 상태에서도 같은 검증을 반복한다.

Xcode, 시뮬레이터, 서명, iPhone 보안 승인과 실제 문자 자동화 검증을 모두 완료했다.

## 4. 구현 단계

### 단계 1. 순수 Swift 문자 파서

구현 범위:

- 거래 종류, 카드 끝 네 자리, 금액, 월/일, 시각, 가맹점, 선택적 잔액을 표현하는 파싱 결과
- 승인 문자 파서
- 승인취소 문자 파서
- 지원하지 않는 형식에 대한 실패 결과
- 원문의 공백 및 줄바꿈 정규화
- 파서 버전 표시

검증 기준:

- 요구사항 문서의 실제 문자 세 건이 예상값으로 파싱된다.
- 승인취소의 거래 시각은 `없음`으로 남는다.
- 형식이 잘못된 문자가 예외나 앱 종료를 일으키지 않는다.
- 금액의 쉼표, `원`, 마침표를 안전하게 처리한다.

이 단계는 현재 명령행 도구만으로 완료할 수 있다.

### 단계 2. 최소 iOS 앱과 로컬 저장

구현 범위:

- `CherryPicker` iOS 앱 프로젝트
- SwiftData 거래 모델
- 원문을 가장 먼저 저장한 뒤 파싱 결과를 함께 기록하는 저장 서비스
- 중복 방지 키와 10분 중복 판정
- 저장된 거래를 최신 수신 순으로 보여주는 진단용 단일 목록 화면
- 승인/취소, 금액, 가맹점, 파싱 성공 여부 표시
- 저장소 단위 테스트

검증 기준:

- 앱 재실행 후에도 저장한 거래가 남는다.
- 파싱 실패 원문도 목록에 남는다.
- 같은 원문을 10분 이내 두 번 저장하면 한 건만 생성된다.
- 제공된 세 문자를 앱 내부 테스트 입력으로 저장해 확인할 수 있다.

### 단계 3. App Intent 연동

구현 범위:

- 단축어에 노출되는 `거래 문자 저장` App Intent
- 필수 문자열 매개변수 `문자 원문`
- 백그라운드 실행 모드
- 단계 2와 동일한 저장 서비스 호출
- 저장 성공, 중복 무시, 실패 결과 반환

검증 기준:

- 단축어 앱에서 CherryPicker의 동작을 찾을 수 있다.
- 앱을 직접 열지 않고 테스트 문자열을 저장할 수 있다.
- 실행 결과가 단축어에 표시된다.
- App Intent로 저장한 결과가 앱 목록에 나타난다.

### 단계 4. 실제 문자 자동화 검증

사용자와 함께 iPhone에서 설정할 범위:

1. 단축어 앱에서 메시지 개인용 자동화를 만든다.
2. MG카드 문자 발신자 또는 본문 조건을 설정한다.
3. 수신한 메시지 내용을 `거래 문자 저장`에 연결한다.
4. 실행 전 묻기를 끄고 자동 실행을 허용한다.

시험 매트릭스:

| 상황 | 승인 | 취소 | 기대 결과 |
|---|---:|---:|---|
| 앱이 열린 상태 | 시험 | 시험 | 즉시 한 건 저장 |
| 앱이 백그라운드 | 시험 | 시험 | 앱 전환 없이 저장 |
| iPhone 잠금 상태 | 시험 | 시험 | 잠금 해제 요구 없이 저장 |
| 같은 자동화 재실행 | 시험 | 선택 | 중복 생성 없음 |
| 알 수 없는 형식 | 시험 | 해당 없음 | 원문과 실패 상태 저장 |

실패 시 확인할 정보:

- 단축어 실행 기록과 오류 메시지
- 앱의 마지막 저장 시도 시각
- 파싱 성공 여부와 원문 해시
- 잠금 상태, 저전력 모드 및 앱 강제 종료 여부

### 단계 5. 기술 검증 정리

구현 결과를 문서화한다.

- 성공한 실행 조건
- 실패하거나 사용자 확인이 필요한 조건
- 실제 수신 메시지의 추가 변형
- 데이터 유실 및 중복 여부
- 다음 MVP 화면 구현으로 진행할지 여부
- 필요한 경우 저장 또는 자동화 방식 변경안

## 5. 파일 및 모듈 구조 초안

Xcode 준비 전에는 파서 코어를 로컬 Swift Package로 구성한다. 이후 iOS 앱이 이 패키지를 로컬 의존성으로 사용하고, 앱 전용 코드는 Xcode 프로젝트 안에 둔다. 실제 그룹 이름은 Xcode 버전에 맞게 조정할 수 있다.

```text
Package.swift
Sources/
  CherryPickerCore/
    TransactionKind.swift
    ParsedTransaction.swift
    MGCardMessageParser.swift
Tests/
  CherryPickerCoreTests/
    MGCardMessageParserTests.swift
CherryPickerApp/
  App/
    CherryPickerApp.swift
  Persistence/
    TransactionRecord.swift
    TransactionStore.swift
  Intents/
    SaveCardMessageIntent.swift
  Features/
    Inbox/
      InboxView.swift
  Tests/
    TransactionStoreTests.swift
```

파서 패키지는 Foundation 외 프레임워크에 의존하지 않는다. 모델과 파싱까지만 담당하고, 저장 및 UI 책임은 iOS 앱에 남긴다.

- 카드 현황 대시보드
- 실적 및 혜택 편집 화면
- 카드 약관 검색
- 승인취소 원거래 추천과 연결
- 백업, 내보내기 및 iCloud 동기화
- 완성형 온보딩과 디자인 시스템
- 두 번째 카드 또는 카드사 파서

이 기능들은 문자 수집이 실제 기기에서 안정적으로 동작한 뒤 구현한다.

## 7. 위험 요소와 대응

### 잠금 상태에서 자동화 또는 저장 실패

- 가장 먼저 실기기에서 확인할 핵심 위험이다.
- 실패하면 원인을 단축어 트리거, App Intent 실행, SwiftData 접근으로 나눠 시험한다.
- 필요하면 App Intent의 저장소를 앱 그룹 파일 또는 다른 로컬 저장 방식으로 변경한다.

### 문자 본문이 예상과 다르게 전달됨

- 원문 전체를 먼저 보존하고 파싱은 이후 단계로 취급한다.
- 줄바꿈과 마침표 변형을 허용하는 파서를 사용한다.
- 알 수 없는 형식도 수집함에 남긴다.

### 취소 원거래를 확정할 수 없음

- 취소는 독립 거래로 저장하고 원승인을 자동 또는 수동으로 연결하지 않는다.
- 실적 `인정` 취소는 취소 발생 기간의 실적에서 차감하며 결과가 음수여도 유지한다.
- 취소 금액은 혜택 합계를 자동으로 조정하지 않는다.

### 중복 판정의 오탐

- 원문 해시뿐 아니라 10분 시간 창을 함께 사용한다.
- 기술 검증 기록에서 중복으로 무시한 결과를 확인할 수 있게 한다.

## 8. 작업 완료 정의

이번 기술 검증은 다음 조건을 모두 충족하면 완료한다.

- 실제 문자 세 건에 대한 파서 자동 테스트가 통과한다.
- 앱, 백그라운드 및 잠금 상태의 결과가 각각 기록된다.
- 승인 및 취소 원문이 로컬에 저장된다.
- 파싱 실패 시에도 원문이 유실되지 않는다.
- 동일 입력 재실행 시 중복이 생성되지 않는다.
- 실기기 결과와 발견된 제약이 문서화된다.
- 다음 MVP 기능 구현 여부를 판단할 수 있다.

## 9. 확정된 결정

사용자 검토를 통해 다음과 같이 확정했다.

1. 최소 지원 버전은 iOS 27로 한다.
2. 통장 잔액이 포함된 문자 원문은 기기에 보존하되 기본 화면에서는 숨긴다.
3. Xcode 준비 전 파서와 테스트를 먼저 구현하고, Xcode 27 준비 후 앱을 이어서 구현한다.

4. 번들 식별자는 `dev.cherrypicker.local`, 개발 팀은 사용자의 Personal Team으로 설정한다.
5. 앱은 iPhone 전용 세로 화면으로 빌드한다.
6. 취소 원승인 매칭은 MVP에서 제외하고, 인정된 취소 금액을 취소 발생 기간의 음수 실적으로 계산한다.
7. 취소 금액은 혜택 합계를 자동으로 조정하지 않는다.
