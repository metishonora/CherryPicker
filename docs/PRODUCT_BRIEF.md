# CherryPicker 초기 제품 구상서

- 문서 상태: 합의된 초기 방향 기록
- 대상: 개인용
- 기준일: 2026-07-31

## 1. 만들고자 하는 것

CherryPicker는 사용자가 보유한 카드와 실제 사용 내역에 특화하여, 카드별 사용 실적과 받은 혜택을 정확하게 기록하고 확인하는 개인용 도구다.

기존의 대중적인 카드 사용량 확인 앱에서는 실제 카드 내역이나 사용처만으로 다음 내용을 정확히 알기 어렵다는 문제에서 출발한다.

- 해당 거래가 카드 실적으로 인정되는지
- 해당 거래에서 혜택을 받았는지
- 실제로 받은 혜택이 무엇인지
- 카드별 사용 실적이 현재 어느 정도인지

## 2. 사용자와 환경

- 본인 한 명이 사용하는 개인용 앱으로 만든다.
- 주 사용 기기는 iPhone이다.
- 최초 지원 카드 종류는 이후에 선정한다.

## 3. 거래 수집 방향

iOS 앱은 다른 카드사 앱의 푸시 알림을 직접 읽지 않는다.

초기 구상은 카드 승인 문자를 iPhone 단축어 자동화로 받아 CherryPicker에 전달하는 방식으로 진행한다.

```text
카드 승인 문자 수신
  → iPhone 단축어 자동화 실행
  → CherryPicker의 거래 저장 기능 호출
  → 앱에서 거래 내역 확인 및 분류
```

사용자는 카드사 또는 문자 발신자에 맞는 자동화를 최초 한 번 설정한다. 이후에는 거래마다 공유하거나 복사하지 않아도 자동으로 수집되는 사용 경험을 목표로 한다.

CherryPicker는 iPhone 단축어에서 호출할 수 있는 거래 저장 기능을 제공한다.

## 4. 거래 판정 방향

실적 인정 여부와 혜택 적용 여부는 카드사 정책, 카드 상품별 조건, 가맹점 분류 및 실제 사용 경험을 함께 고려해야 한다.

이 때문에 초기 제품에서는 앱이 판정을 자동으로 확정하지 않는다.

- 사용자가 거래 내역을 나중에 직접 분류한다.
- 사용자가 실적 인정 여부를 기록한다.
- 사용자가 혜택을 받았는지 기록한다.
- 사용자가 확인한 내용을 최종 판정으로 사용한다.

자동 분석 기능이 추가되더라도 사용자의 판단을 돕는 힌트로 사용하며, 사용자 판정을 임의로 덮어쓰지 않는다.

## 5. 약관 활용 방향

카드 약관이나 카드사의 공식 안내를 검색하여 다음 판정에 참고할 수 있는 힌트를 제공한다.

- 실적 인정 또는 제외 조건
- 혜택 적용 조건
- 카드 상품별 유의사항

약관 검색 결과는 참고 정보이며, 실제 거래의 실적 인정 여부나 혜택 지급 여부를 자동으로 확정하지 않는다.

약관 검색 기능은 거래 수집 및 사용자 분류 기능 이후에 다룬다.

## 6. 데이터 처리 방향

- 개인용 사용을 전제로 한다.
- 초기 방향은 외부 서버 없이 개인 기기 중심으로 데이터를 보관하는 것이다.
- 회원가입, 로그인 및 다중 사용자 기능은 초기 범위에 포함하지 않는다.

구체적인 저장 기술, 백업 방식 및 보안 설계는 다음 세션에서 결정한다.

## 7. 초기 범위에서 제외하는 것

- 카드사 앱 푸시 알림 직접 수집
- 카카오톡 알림톡 직접 수집
- 금융결제원, 오픈뱅킹 또는 마이데이터 운영 연동
- 카드 정책에 따른 실적 및 혜택의 완전 자동 확정
- 회원가입 및 다중 사용자 기능
- 최초 지원 카드의 확정
- 세부 기술 아키텍처의 확정

## 8. 다음 세션에서 이어서 할 일

다음 내용은 아직 확정하지 않았으며, 후속 세션에서 실제 검증과 설계를 진행한다.

1. 사용 중인 카드가 승인 문자를 제공하는지 확인한다.
2. 실제 승인 문자 형식을 확보한다.
3. iPhone 단축어가 문자를 자동으로 감지하고 내용을 전달할 수 있는지 시험한다.
4. 잠금 및 백그라운드 상태에서도 자동화가 동작하는지 시험한다.
5. 단축어에서 CherryPicker의 거래 저장 기능을 호출하는 최소 기능을 검증한다.
6. 검증 결과를 바탕으로 앱 아키텍처와 저장 방식을 설계한다.
7. 최초 지원 카드를 선정한다.
8. 거래 분류 화면과 카드별 현황 화면의 상세 요구사항을 정한다.
