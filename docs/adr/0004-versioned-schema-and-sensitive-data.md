# ADR-0004: V1 데이터를 보존하는 버전 스키마와 로컬 민감정보 원칙을 사용한다

- 상태: 승인됨
- 날짜: 2026-08-05

## 맥락

현재 스키마는 VersionedSchema 없이 실제 iPhone에 데이터를 저장했다. Card, 사용자 override, 취소 관계를 추가하면서 이 데이터를 잃으면 문자 수집 검증 결과와 사용자 판정이 사라진다. 원문에는 마스킹된 이름과 통장 잔액도 포함될 수 있다.

## 결정

현재 TransactionRecord 모델을 V1로 고정하고 V2부터 SwiftData VersionedSchema와 SchemaMigrationPlan을 사용한다. V1 디스크 fixture로 migration을 자동 검증한다. V1의 `hasUserEdits == true` 거래는 현재 편집 필드를 모두 override로 복사해 데이터 보존을 우선한다. 관계와 신규 필드는 선택적으로 추가하고 후속 backfill은 idempotent하게 작성한다.

Migration 실패 시 저장 파일을 삭제하거나 새 빈 저장소로 대체하지 않는다. 오류를 사용자에게 명시하고 원본 저장소를 보존한다.

원문은 재파싱과 진단을 위해 로컬에 보존하되 기본 목록, 대시보드, 로그에서 숨긴다. CloudKit과 외부 서버 전송을 사용하지 않는다. 거래를 사용자가 삭제하면 해당 원문도 삭제한다. 기존 혜택 숫자는 원화와 포인트를 구분할 근거가 없으므로 `legacyUnspecified` 단위로 보존한다. 향후 백업·내보내기는 원문 포함 여부를 별도 결정한다.

## 결과

- 실제 기기 데이터 보존을 자동으로 검증할 수 있다.
- 모든 후속 모델 변경에 스키마 버전과 migration 단계가 필요하다.
- 원문 기반 재파싱은 유지되지만 기기에 민감 정보가 남으므로 노출 경계를 계속 시험해야 한다.
- 백업·복구 자체는 MVP 범위 밖이며 별도 기능 결정이 필요하다.

## 고려한 대안

- 기존 저장소 삭제 후 재생성: 데이터 보존 완료 조건에 어긋나 제외했다.
- 원문을 파싱 직후 제거: 실패 진단과 파서 개선 재처리를 막아 제외했다.
- CloudKit 동기화: 개인 기기 중심 MVP 범위를 넓혀 제외했다.
