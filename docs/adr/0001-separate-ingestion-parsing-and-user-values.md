# ADR-0001: 거래 사실, 파싱 스냅샷, 사용자값을 분리한다

- 상태: 승인됨
- 날짜: 2026-08-05

## 맥락

현재 TransactionRecord는 파싱값과 사용자가 수정한 값을 같은 속성에 저장하고 `hasUserEdits` 하나로 재파싱을 차단한다. 한 필드를 수정해도 나머지 필드의 새 파싱 결과를 적용할 수 없고, V1 값만 보고 어느 값이 사용자의 것인지 알 수 없다.

## 결정

Transaction을 논리적으로 세 층으로 나눈다.

1. UUID, 수신 시각, 원문, 지문으로 구성된 불변 수집 사실
2. 파서 버전과 함께 교체할 수 있는 파싱 스냅샷
3. 필드별 사용자 override, 카드 배정, 판정, 메모로 구성된 사용자 데이터

화면과 도메인 서비스에는 `사용자 override ?? 파싱값`을 적용한 Sendable TransactionSnapshot만 전달한다. 값 제거가 가능한 필드는 override 존재 여부를 별도로 저장한다. 파서와 재처리는 사용자 데이터와 승인취소 연결을 변경할 수 없다.

Card와 Transaction은 UUID로 식별한다. Transaction의 Card 관계는 선택적이며 Card 삭제 시 nullify한다. 취소는 독립 Transaction이고 사용자 확인을 받은 경우에만 최대 한 승인과 연결한다. 승인은 여러 취소의 원본이 될 수 있다.

## 결과

- 사용자 수정값을 보존하면서 새 파서 결과를 적용할 수 있다.
- 파싱 실패와 카드 미배정 거래를 데이터 손실 없이 유지한다.
- 부분취소 정책을 나중에 정해도 관계 구조를 바꾸지 않는다.
- 모델과 매핑 코드가 늘고, V1의 `hasUserEdits == true` 거래는 모든 현재 편집 필드를 override로 이관해야 한다.

## 고려한 대안

- 단일 `hasUserEdits`: 단순하지만 필드별 소유권을 표현하지 못해 제외했다.
- 사용자 편집 시 파싱값 폐기: 원문 재처리와 진단 능력을 잃어 제외했다.
- 승인과 취소를 한 레코드로 합치기: 원거래를 특정할 수 없는 취소를 보존할 수 없어 제외했다.
