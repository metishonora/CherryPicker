# ADR-0005: 취소를 원승인 연결 없이 현재 기간의 음수 실적으로 계산한다

- 상태: 승인됨
- 날짜: 2026-08-11

## 맥락

취소 문자에는 원승인 식별자와 완료 시각이 없다. 카드, 금액, 날짜와 가맹점 유사도로 후보를 만들 수는 있지만 부분취소, 여러 취소, 기간을 넘긴 취소와 동점 후보 때문에 사용자가 원승인을 찾아 연결하는 과정이 복잡해진다.

실제 카드사는 원승인을 특정하지 않아도 취소 금액을 취소 발생 시점의 현재 실적에서 차감한다. 그 결과 기간 실적이 음수가 될 수 있고 사용자는 그만큼 실적을 추가로 채워야 한다. 반면 취소 금액 자체가 혜택을 추가 지급하거나 혜택 합계를 음수로 만들지는 않는다.

V2 스키마에는 선택적 승인–취소 자기 관계가 이미 존재하지만 아직 후보 검색, 연결 명령 또는 UI는 구현되지 않았다.

## 결정

- 취소는 원승인과 연결하지 않는 독립 Transaction으로 저장하고 검토한다.
- MVP에서는 원승인 후보 검색과 연결·변경·해제 기능을 구현하지 않는다.
- 사용자가 실적 `인정`으로 확정한 승인은 금액을 더하고, 실적 `인정`으로 확정한 취소는 금액을 뺀다.
- 취소는 원승인 기간을 수정하지 않고 취소 거래가 속한 실적 기간에 반영한다.
- 기간 실적이 음수여도 0으로 보정하지 않으며 남은 목표 금액 계산에 그대로 사용한다.
- 취소 금액은 혜택 합계를 자동으로 차감하거나 증가시키지 않는다. 혜택 합계는 사용자가 `받음`으로 확정한 혜택 값만 반영한다.
- V2의 선택적 승인–취소 관계는 제거하거나 backfill하지 않고 향후 확장용으로 남긴다. MVP 집계는 이 관계를 읽지 않는다.

## 결과

- 원승인 후보 점수, 검색 범위, 부분취소 연결과 연결 상태 UI가 필요하지 않다.
- 전월 승인 취소도 취소 발생 기간에 반영되므로 원승인 기간을 다시 계산하지 않는다.
- 기간 실적이 음수일 때 남은 목표 금액이 취소 금액만큼 증가한다.
- 기존 V2 스키마를 되돌리지 않으므로 추가 migration이 필요하지 않다.
- 원승인별 취소 이력이나 원거래 대조가 필요해지면 선택적 관계를 사용하는 별도 기능으로 다시 결정한다.

## 고려한 대안

- 유사도 기반 원승인 후보와 사용자 연결: 정확성을 보장할 수 없고 MVP 검토 흐름이 커져 제외했다.
- 취소를 원승인 기간에 소급 반영: 원승인 식별자가 없어 연결 기능 없이는 안정적으로 계산할 수 없어 제외했다.
- 음수 실적을 0으로 제한: 카드사가 요구하는 추가 실적을 표현하지 못해 제외했다.
