# ADR-0002: 날짜·후보·집계를 파생 정책으로 분리한다

- 상태: 승인됨
- 날짜: 2026-08-05

## 맥락

문자에는 연도가 없고 취소에는 시각과 원승인 식별자가 없다. 실적 기간, 후보 점수, 취소의 집계 방식도 기능 검증에 따라 달라질 수 있다. 이 정책들을 SwiftData 모델이나 SwiftUI에 넣으면 정책 변경이 스키마와 화면의 재작업으로 이어진다.

## 결정

수집·파싱·사용자 판정처럼 재현에 필요한 사실만 저장한다. 다음 결과는 CherryPickerCore의 순수 Sendable 서비스가 계산한다.

- TransactionDateResolver: 부분 날짜를 버전 있는 해석 결과로 변환
- PerformancePeriodResolver: 카드의 기간 규칙을 시작 포함·끝 미포함 구간으로 변환
- CancellationMatcher: 저장된 승인 스냅샷에서 정렬된 후보 생성
- DashboardCalculator: 카드·기간·거래 스냅샷과 정책으로 현황 생성

대시보드 합계와 후보 점수는 저장하지 않는다. 날짜 해석 결과는 과거 거래가 앱 업데이트만으로 다른 기간으로 이동하지 않도록 해석 출처와 resolver 버전과 함께 저장한다. 사용자 날짜 override는 항상 우선한다.

## 결과

- #2·#3·#4가 정책을 독립적으로 확정하고 테스트할 수 있다.
- 정책 변경이 SwiftData migration을 요구하지 않는다.
- 집계는 입력이 바뀔 때 다시 계산해야 하지만 MVP 데이터 규모에서는 수용한다.
- 혜택은 단위별로 계산하며 서로 다른 단위를 암묵적으로 더하지 않는다.

## 고려한 대안

- 집계 레코드 저장: 캐시 무효화와 동시성 상태가 늘어 MVP에서는 제외했다.
- 후보 점수 저장: 파라미터 변경 때 오래된 점수가 남아 제외했다.
- 연도를 조회할 때마다 추론: 같은 거래가 앱 버전에 따라 다른 기간으로 이동할 수 있어 제외했다.
